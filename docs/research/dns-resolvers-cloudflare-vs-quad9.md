## What gets blocked and where the data comes from

### Cloudflare 1.1.1.2 and 1.1.1.3 ("1.1.1.1 for Families")

- Cloudflare's docs say Families "automatically blocks DNS queries to domains associated with malware, phishing, or (optionally) adult content". 1.1.1.2 is "Block malware" and 1.1.1.3 is "Block malware and adult content" ([setup](https://developers.cloudflare.com/1.1.1.1/setup/), [IP addresses](https://developers.cloudflare.com/1.1.1.1/ip-addresses/)).
- A 2024 Cloudflare post describes 1.1.1.2 as protecting against "malware, spam, botnet command and control attacks, or phishing threats". It says 1.1.1.3 "provides all the benefits of 1.1.1.2" and also blocks adult content ([Cloudflare blog, 2024-09-24](https://blog.cloudflare.com/safer-resolver/)).
- Families "is built on top of the same site categorization and filtering technology that powers Cloudflare's Gateway product" ([launch post, 2020-04-01](https://blog.cloudflare.com/introducing-1-1-1-1-for-families/)).
- The categories come from third-party data that Cloudflare licenses ("The data providers that we license content from have different categorizations"). The adult category was meant to "mirror the Google SafeSearch criteria" / CIPA. On launch day the wrong provider category went live, and 1.1.1.3 blocked LGBTQIA+ sites ([Cloudflare blog, 2020-04-02](https://blog.cloudflare.com/the-mistake-that-caused-1-1-1-3-to-block-lgbtqia-sites-today/)). The providers are not named.
- If a domain is miscategorised, you report it through Cloudflare's feedback form. Test domains: `malware.testcategory.com` and `nudity.testcategory.com` ([setup](https://developers.cloudflare.com/1.1.1.1/setup/)).
- Plain 1.1.1.1 does no filtering: "Cloudflare does not block or filter any content through the 1.1.1.1 Public DNS Resolver" ([privacy commitments](https://developers.cloudflare.com/1.1.1.1/privacy/public-dns-resolver/)).

### Quad9 9.9.9.9

- Quad9 blocks "only sites that present a danger to the end user, their equipment, or the network. Quad9 does not block content". Its TI agreements require blocking criteria to be "exclusively security-related". It "does not block advertisements or web trackers" ([threat blocking](https://quad9.net/service/threat-blocking/)).
- The block lists come from commercial and public threat-intel partners. Quad9 is "exclusively a distribution tool for the threat data generated by partners" and does not produce its own IOCs. That page says "around twenty"; the About page says "25+ Threat Intelligence Providers" ([threat blocking](https://quad9.net/service/threat-blocking/), [about](https://quad9.net/about/)).
- The privacy policy limits filtering to "phishing, malware, vulnerability exploit, or fraud". Every blocked domain can be looked up on Quad9's site, which names the TI source that listed it ([privacy policy §5.1, §5.1.1](https://quad9.net/privacy/policy/)).
- Legal exception: Quad9 says it will pull out of a region rather than run censorship it disagrees with ([privacy policy §5.1.1](https://quad9.net/privacy/policy/)). After a French court ruling for beIN, Quad9 announced that "Starting November 24, Quad9 will no longer be able to offer its free cyberprotection service to users located in France" ([Quad9 blog, 2026-10-22](https://quad9.net/news/blog/au-revoir-france/)).

## What a blocked response looks like

| Resolver | Blocked | Doesn't exist | DNSSEC failure |
| --- | --- | --- | --- |
| 1.1.1.2 / 1.1.1.3 | answer `0.0.0.0` | not documented for Families | fails to resolve; EDE 1/2/6/7… attached |
| 9.9.9.9 | `NXDOMAIN`, `AUTHORITY: 0`, EDE 15/16/17 | `NXDOMAIN`, `AUTHORITY: 1` | `SERVFAIL` |

- Cloudflare: "When a queried domain is classified as malicious, Cloudflare returns the address `0.0.0.0` instead of the real address" ([setup](https://developers.cloudflare.com/1.1.1.1/setup/)). The EDE reference page lists only DNSSEC and stale-answer codes, not a "Blocked" code ([extended DNS error codes](https://developers.cloudflare.com/1.1.1.1/infrastructure/extended-dns-error-codes/)).
- Quad9: "When Quad9 blocks a domain, the response is NXDOMAIN … When you receive an NXDOMAIN with AUTHORITY: 0, that is a block from Quad9. When you receive NXDOMAIN with AUTHORITY: 1, then that is a domain that does not exist." DNSSEC failures return `SERVFAIL` ([Quad9 FAQs, "Identifying a Quad9 block"](https://docs.quad9.net/FAQs/)). Quad9 also marks blocked responses with "Extended DNS Error (RFC8914) … 15 (Blocked), 16 (Censored), and 17 (Filtered)" ([privacy policy §5.1](https://quad9.net/privacy/policy/)).

Debug tip: a Cloudflare block looks like a successful lookup, so clients try to connect to `0.0.0.0`. A Quad9 block looks like a missing domain unless you check the AUTHORITY count or the EDE.

## ECS and DNSSEC

### ECS (EDNS Client Subnet)

- Cloudflare 1.1.1.1 does not send ECS: "1.1.1.1 is a privacy-focused resolver and does not include client IP information in its queries to authoritative servers". The only exception is the Akamai debug domain `whoami.ds.akahelp.net` ([FAQ](https://developers.cloudflare.com/1.1.1.1/faq/)). The FAQ covers 1.1.1.1 only. The setup page says "1.1.1.1 for Families uses the same privacy commitments as the standard 1.1.1.1 resolver" ([setup](https://developers.cloudflare.com/1.1.1.1/setup/)), but no page says outright that 1.1.1.2/1.1.1.3 skip ECS.
- Quad9 9.9.9.9 does not send ECS: "we do not transmit that data in our default service" ([Quad9 FAQ](https://quad9.net/support/faq/)). 9.9.9.11 is "Secure + ECS" and 9.9.9.12 is "No Threat Blocking + ECS". Quad9 recommends them only for users who do not route to their closest Quad9 location. ECS does not change which Quad9 PoP you reach ([Quad9 docs FAQs](https://docs.quad9.net/FAQs/), [Services](https://docs.quad9.net/services/)).

### DNSSEC

- Cloudflare: "1.1.1.1 is a DNSSEC-validating resolver. On every query, it sends the `DO` (DNSSEC OK) flag" ([FAQ](https://developers.cloudflare.com/1.1.1.1/faq/)). The same caveat applies: Families is not named on that page.
- Quad9: "DNSSEC validation is enabled on all resolver addresses" ([service addresses](https://quad9.net/service/service-addresses-and-features/)). Before June 15, 2026, 9.9.9.10 did not validate. Since then, 9.9.9.10 and 9.9.9.12 also return `SERVFAIL` on DNSSEC failure. Quad9: "If you need a non-validating resolver for comparison purposes, you will need to use one outside of Quad9's network" ([Quad9 blog, 2026-04-09](https://quad9.net/news/blog/quad9-enables-dnssec-on-all-service-endpoints/)).

## Logging, privacy, jurisdiction, audits

### Cloudflare (1.1.1.1, 1.1.1.2, 1.1.1.3)

- Families "uses the same privacy commitments as the standard 1.1.1.1 resolver" ([setup](https://developers.cloudflare.com/1.1.1.1/setup/)). The launch post says the same ([2020 blog](https://blog.cloudflare.com/introducing-1-1-1-1-for-families/)).
- Client IP "will not be stored in non-volatile storage". IPs are truncated (last octet IPv4, last 80 bits IPv6) and the truncated IP is deleted "within 25 hours". "Public Resolver Logs" (query name, type, response code, source country, source ASN, colo, and more) are deleted within 25 hours, except sampled data that has no truncated IPs and is used for aggregates ([privacy commitments](https://developers.cloudflare.com/1.1.1.1/privacy/public-dns-resolver/)).
- Separately, randomly sampled packets from "at most 0.05% of all traffic" are kept for troubleshooting and DoS mitigation. The 2026 audit post says these include the querying IP address ([privacy commitments](https://developers.cloudflare.com/1.1.1.1/privacy/public-dns-resolver/), [2026 audit post](https://blog.cloudflare.com/1111-privacy-examination-2026/)).
- Logs are shared with no third party except APNIC (anonymised data, research agreement). Personal data is not sold ([privacy commitments](https://developers.cloudflare.com/1.1.1.1/privacy/public-dns-resolver/)).
- Jurisdiction: Families and 1.1.1.1 users agree to the Cloudflare Website and Online Services Terms ([terms of use](https://developers.cloudflare.com/1.1.1.1/terms-of-use/)). Those terms are "governed by the laws of the State of California", with courts in San Francisco County ([website terms §12](https://www.cloudflare.com/website-terms/)). Privacy is governed by the Cloudflare Privacy Policy ([privacy overview](https://developers.cloudflare.com/1.1.1.1/privacy/)).
- Government blocking requests: Cloudflare "would pursue its legal remedies before complying" with requests to block outside Families' filtering scope ([privacy commitments](https://developers.cloudflare.com/1.1.1.1/privacy/public-dns-resolver/)).
- Audits: Cloudflare retained "a Big 4 accounting firm" (not named) to examine 1.1.1.1's privacy commitments. Results were announced in 2020, and the "same Big 4 accounting firm" published another report on 2026-04-01. The 2026 scope "focuses exclusively on our privacy commitments" ([2020 results](https://blog.cloudflare.com/announcing-the-results-of-the-1-1-1-1-public-dns-resolver-privacy-examination/), [2026 results](https://blog.cloudflare.com/1111-privacy-examination-2026/)).

### Quad9 (9.9.9.9 and siblings)

- Operator: "the Swiss foundation Quad9, c/o SWITCH, Werdstrasse 2, 8004 Zürich" ([privacy policy](https://quad9.net/privacy/policy/)).
- "Quad9 does not collect or record user IP addresses, nor does it collect or hold any proxy for or representation of user IP addresses". The source IP stays in volatile memory for "microseconds to milliseconds" ([privacy policy §1.0, §2.1](https://quad9.net/privacy/policy/)).
- What Quad9 does keep is integer counters by PoP, by prefix no more specific than /24 (IPv4) or /56 (IPv6) plus ASN, by geographic region, by qtype, by response code, by protocol, and by filter-list match. It also keeps first and last seen timestamps per query label. It does not share NXDOMAIN qnames with third parties ([privacy policy §2.2, §2.3.3](https://quad9.net/privacy/policy/)). The FAQ says Quad9 logs geolocation (city, state, country) for threat analysis and TI partner feedback ([FAQ](https://quad9.net/support/faq/)).
- Quad9 does not "share, sell, or rent any information that could identify an individual user". Aggregates go to TI partners and vetted researchers ([privacy policy §2.3](https://quad9.net/privacy/policy/)).
- Jurisdiction: "entirely and fully subject to Swiss data protection law including the Swiss Federal Act on Data Protection (FADP)", supervised by the FDPIC, and "also specifically subject to the GDPR" for EU/EEA users. Swiss findings of law say the surveillance act (SPTA) and the telecom act (TCA, KYC rules) do not apply to Quad9. Foreign requests must go through MLAT via the Swiss Federal Office of Justice ([compliance and applicable law](https://quad9.net/privacy/compliance-and-applicable-law/)).
- No mandatory attribution: Quad9 "will not cooperate with any efforts that force mandatory attribution" ([privacy policy §5.1.1](https://quad9.net/privacy/policy/)).
- Transparency: Quad9 publishes a [transparency report](https://quad9.net/about/transparency-report/). The pages above do not mention any independent third-party privacy audit.

## SafeSearch / YouTube Restricted Mode on 1.1.1.3

- SafeSearch: in a 2024 post, Cloudflare says 1.1.1.3 blocks adult content "from both direct site navigation, as well as locking public search engines to Safe Search only" ([Cloudflare blog, 2024-09-24](https://blog.cloudflare.com/safer-resolver/)). The current [setup](https://developers.cloudflare.com/1.1.1.1/setup/) and [FAQ](https://developers.cloudflare.com/1.1.1.1/faq/) pages do not mention SafeSearch. Which search engines are covered is not documented.
- YouTube Restricted Mode: none of the Cloudflare primary sources checked say that 1.1.1.3 enforces it. Cloudflare documents Safe Search and YouTube Restricted Mode as Gateway (Zero Trust) DNS policy actions ([Gateway DNS policies](https://developers.cloudflare.com/cloudflare-one/traffic-controls/dns-policies/)), not as features of the public resolvers.
- Neither 1.1.1.2 nor Quad9 claims any SafeSearch enforcement. Quad9 says it "does not block content" ([threat blocking](https://quad9.net/service/threat-blocking/)).

## Homelab notes

- This stack already runs AdGuard Home ([services](../services.md)). Set any of these as its upstream. Prefer DoH/DoT so your ISP cannot see or tamper with upstream queries.
- Pick one block format and learn its signature. `0.0.0.0` (Cloudflare) can look like a broken service. `NXDOMAIN` with `AUTHORITY: 0` (Quad9) can look like a typo.
- Don't mix 1.1.1.2 and 9.9.9.9 as "primary/secondary" in one forwarder: they use different block lists and different block formats, so results become non-deterministic.
- Traefik's ACME DNS-01 propagation check uses `1.1.1.1:53` (`config/traefik/traefik.acme.yml`). That is the unfiltered resolver, which is correct for that job. Leave it alone.
- Quad9 users in France lose service from 2026-11-24 ([Quad9 blog](https://quad9.net/news/blog/au-revoir-france/)).

## Not confirmed

These could not be verified from a primary source, or the sources contradict each other:

- **1.1.1.2/1.1.1.3 ECS and DNSSEC.** The ECS and DNSSEC statements in the FAQ name only 1.1.1.1. That Families behaves the same is an inference from "same privacy commitments", not a documented fact.
- **What Cloudflare returns for blocked AAAA queries** (for example `::`). The docs mention only `0.0.0.0`.
- **Whether Cloudflare attaches an EDE code to Families blocks.** Not in the EDE reference.
- **Whether the Big 4 privacy examination covers 1.1.1.2/1.1.1.3.** The audit posts and privacy page cover only the "1.1.1.1 Public DNS Resolver". The auditor's name is not given in any page checked.
- **Which threat-intel or categorisation vendors Cloudflare uses.** Only "data providers that we license content from" is stated.
- **Which search engines 1.1.1.3 forces into SafeSearch, and whether it still does.** The only primary source is the 2024 blog post.
- **YouTube Restricted Mode on 1.1.1.3.** No primary source confirms or denies it for the public resolver.
- **Quad9 9.9.9.11 ECS prefix length.** Not stated on the pages checked.
- **Any independent third-party audit of Quad9's privacy practices.** None found on quad9.net.
- **The exact number of Quad9 TI partners.** "around twenty" ([threat blocking](https://quad9.net/service/threat-blocking/)) vs "20+" / "25+" ([about](https://quad9.net/about/)).
